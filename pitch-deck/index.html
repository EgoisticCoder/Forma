F / THE GAP

01 — THE PROBLEM

Agents change the code.
Who checks the interface?

A page can compile, pass unit tests, and still feel broken: the mobile layout overflows, a call to action disappears, or the visual hierarchy falls apart.

01 / OUTPUT GAPCode is not the experience.

Frontend quality is judged in a live browser, across viewports and user states.

02 / FEEDBACK GAPVisual review is manual.

Developers switch between editor, browser, DevTools, screenshots, and checklists.

03 / AGENT GAPMost loops stop at the diff.

Code agents can edit quickly; reliable visual validation is still a separate step.

F / HOW WE LEARN

08 — VALIDATION PLAN

Make quality measurable.

01 / GENERALIZATIONUnseen sites and components

Evaluate pages outside the training list across industries, frameworks, and viewports.

02 / SPECIFICITYEvidence, not boilerplate

Flag repeated language, missing element evidence, and unsupported numeric claims.

03 / AGREEMENTHuman-reviewed labels

Compare issue categories and severity against reviewers; publish limitations with results.

04 / UTILITYDid the fix help?

Measure post-edit regressions, score changes, and developer-rated usefulness.

05 / SAFETYPermission and privacy

Test local-host safeguards, secret handling, and safe MCP tool boundaries.

06 / ECONOMICSInference cost and latency

Measure Kaggle T4 viability, tunnel uptime, queue time, and local alternatives.
